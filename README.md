# LLMS.txt Editor — 1.1.1

**Автор:** Valery Molodtsov  
**Сайт:** https://ворд-пресс.рф

Лёгкий плагин WordPress, который создаёт физический `llms.txt` в публичном корне сайта и позволяет редактировать его через отдельный пункт **LLMS.txt** слева в админке.

## Установка и обновление

1. **Плагины → Добавить новый → Загрузить плагин**.
2. Загрузите `llms-txt-editor-v1.1.1.zip`, подтвердите замену старой версии, если WordPress попросит.
3. Откройте **LLMS.txt** в меню слева, при необходимости сохраните текст.
4. Проверьте `https://ваш-домен/llms.txt` — кириллица должна отображаться корректно.

## Изменения в версии 1.1.1

- После кнопки **«Сохранить llms.txt»** редактор и введённый текст остаются на странице: больше нет перенаправления после POST.
- После успешного сохранения сверху появляется сообщение **«Файл llms.txt сохранён»** со ссылкой на опубликованный файл.
- Рядом с кнопкой сохранения всегда находится ссылка **«Открыть llms.txt ↗»** (открывается в новой вкладке).
- Если сохранить не удалось, введённый текст сохраняется в поле, а ошибка отображается над редактором.

## Исправление кодировки в версии 1.1.0

В версии 1.0.0 WordPress сохранял исходный текст как UTF-8, но веб-сервер мог передавать физический файл `llms.txt` с неверным HTTP charset (например, Windows-1251). В таком случае русский текст в браузере превращается в «Р…» — даже если байты на диске правильные.

- Плагин сохраняет **UTF-8 без BOM** и проверяет данные на валидность UTF-8.
- Для **Apache** добавляет в корневой `.htaccess` только отдельный блок `# BEGIN LLMS TXT EDITOR` / `# END LLMS TXT EDITOR` с `Content-Type: text/plain; charset=UTF-8` для `llms.txt`. Остальные файлы `.txt` не затрагиваются.
- Правило автоматически добавляется при активации или открытии страницы редактора после обновления. Если `.htaccess` не редактируется, админка показывает предупреждение.
- **Nginx**, если самостоятельно отдаёт статические файлы, не читает `.htaccess`. Тогда настройте заголовок в конфигурации Nginx:

```nginx
location = /llms.txt {
    types { }
    default_type "text/plain; charset=utf-8";
    try_files $uri =404;
}
```

Применение конфигурации Nginx и очистка CDN-кэша осуществляются администратором сервера. Заголовок проверить командой:

```bash
curl -I https://example.com/llms.txt
```

Нужен HTTP 200 и `Content-Type: text/plain; charset=utf-8`.

Если **неверные символы уже попали в сам файл**, а не только в отображение браузера, восстановите текст из правильного исходника в редакторе. Сам плагин не пытается автоматически перекодировать существующий контент: это могло бы повредить корректный файл.

## Ограничения и безопасность

- Редактирование доступно только пользователям с правом `manage_options`; используется WordPress nonce.
- Нет базы данных, внешних запросов, фоновых задач и дополнительных зависимостей.
- Максимальный размер 1 МБ; блокируется запись через символические ссылки в `llms.txt`.
- Существующий `llms.txt` при активации не перезаписывается; после отключения или удаления плагина он остаётся на сервере.
- Настройка `.htaccess` остаётся после удаления плагина, поскольку нужен корректный charset сохранённого файла. Для удаления правила вручную удалите соответствующий блок с маркерами.
- В WordPress Multisite один физический файл в общем корне не может содержать разный текст для разных доменов.
