# LLMS.txt Editor

**Версия:** 1.2.0  
**Автор:** Valery Molodtsov  
**Сайт проекта:** [ворд-пресс.рф](https://ворд-пресс.рф)  
**Лицензия:** GPL-2.0-or-later

Лёгкий плагин WordPress для редактирования `llms.txt` в отдельном разделе админки. Позволяет проверить, отдаёт ли веб-сервер файл как `text/plain; charset=UTF-8`, и исправить ситуацию одним нажатием **только если конфигурация сервера позволяет WordPress обслуживать несуществующие `.txt`-адреса**.

## Установка

1. Скачайте **[установочный ZIP v1.2.0](dist/llms-txt-editor-v1.2.0.zip)** (не архив исходного репозитория).
2. В WordPress: **Плагины → Добавить новый → Загрузить плагин**.
3. Установите ZIP и активируйте. При обновлении поверх старой версии подтвердите замену.
4. Откройте пункт **LLMS.txt** слева и при необходимости отредактируйте содержимое.

При активации плагин создаёт физический `/llms.txt` только если его ещё нет. Уже существующий файл **не перезаписывается**.

## Возможности

- Редактирование UTF-8-текста (без BOM) с помощью обычного поля и кнопки **«Сохранить llms.txt»**.
- Текст не исчезает после сохранения; сообщение об успешной записи остаётся на странице.
- Ссылка **«Открыть llms.txt ↗»** открывает опубликованную версию в новой вкладке. Для обхода возможного кэширования используется уникальный параметр URL.
- HTTP-проверка реального публичного адреса с определением статуса `Content-Type` и `charset` (до 8 секунд, результат кэшируется на 5 минут).
- Инструкция Nginx для ручной настройки при отсутствии `charset=UTF-8`.
- Опциональная, **только по явному согласию администратора**, виртуальная выдача через WordPress.

## Как работает решение без изменения Nginx

Если Nginx отдаёт физический `llms.txt` без `charset=UTF-8`, на странице редактора появляется кнопка **«Согласен — включить выдачу через WordPress»**.

После нажатия плагин:

1. Проверяет, попадает ли запрос несуществующего `.txt`-адреса в WordPress. Если нет — показывает ошибку и **ничего не переключает**.
2. Сохраняет исходный текст в базе WordPress, временно переименовывает исходный файл и включает виртуальный обработчик `/llms.txt`.
3. Проверяет реальный HTTP-ответ нового адреса: код `200`, заголовки виртуального обработчика, `Content-Type: text/plain; charset=UTF-8`.
4. Если проверка не прошла, **возвращает физический файл и старый режим**.
5. Если проверка прошла, удаляет временную копию. С этого момента `/llms.txt` генерируется из сохранённого текста WordPress, а отдельного физического файла нет.

Можно нажать **«Вернуться к физическому файлу»**. При обычной деактивации плагин также восстанавливает физический файл; если восстановление невозможно, деактивация блокируется с сообщением об ошибке.

**Ограничение:** на некоторых хостингах Nginx отвечает `404` на все отсутствующие `.txt`-файлы и не передаёт такие запросы в WordPress. В таком случае автоматическое переключение невозможно. Плагин не может менять заголовки физического файла, который Nginx отдаёт напрямую: понадобится конфигурация Nginx или обращение в поддержку хостинга. Никаких обходных переписываний текста или добавления BOM плагин не выполняет.

## Как настроить Nginx вручную

Добавьте в соответствующий блок `server {}` (возможны адаптации под конкретный хостинг):

```nginx
location = /llms.txt {
    types { }
    default_type text/plain;
    charset utf-8;
    try_files $uri =404;
    expires 1h;
}
```

Примените конфигурацию, при необходимости очистите CDN/прокси-кэш и проверьте:

```sh
curl -I 'https://example.com/llms.txt?check=1'
```

Ожидаемый ответ: `200` и `Content-Type: text/plain; charset=utf-8`.

Для Apache плагин сохраняет совместимость с версией 1.1: на физический файл устанавливается отдельное правило `.htaccess`. Nginx **не использует** `.htaccess`.

## Безопасность и ограничения

- Изменения доступны только администраторам с правом `manage_options`; POST-запросы защищены WordPress nonce.
- Проверка выполняется сервером WordPress через `wp_remote_head()` / `wp_remote_get()` к собственному публичному домену. Если у хостинга заблокированы loopback-запросы, статус может остаться неопределённым, а автоматическое переключение не сработает.
- Контент не более 1 МБ; используются проверки UTF-8, типов файлов и символических ссылок.
- Физический файл может кэшироваться сервером, Nginx или CDN — заголовки и очистка кэша при необходимости настраиваются на сервере.
- Виртуальная версия зависит от **работающего WordPress и активного плагина**. Перед удалением/обновлением вручную сначала вернитесь к физическому файлу.
- Для WordPress Multisite с общим физическим корнем возможен конфликт разных сайтов по одному `/llms.txt`.
